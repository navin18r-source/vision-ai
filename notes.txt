MODEL SELECTION & TECHNOLOGY CHOICES

This document explains the rationale behind each AI model and technology choice
in the VISION pipeline.


TABLE OF CONTENTS

1. Super-Resolution: Real-ESRGAN
2. Generative Enhancement: Stable Diffusion + ControlNet
3. Background Removal: U2-Net (rembg)
4. Vision Language Model: MiniCPM-V / LLaVA
5. Virtual Try-On Implementation
6. Summary Table


--------------------------------------------------
1. SUPER-RESOLUTION: REAL-ESRGAN
--------------------------------------------------

WHY REAL-ESRGAN?

Real-ESRGAN (Real-World Enhanced Super-Resolution GAN) was chosen for upscaling
degraded jewelry images.

QUALITY:
- Excellent detail recovery

SPEED:
- Fast (~1–2 seconds per image)

ARTIFACTS:
- Minimal artifacts compared to older models

REAL-WORLD HANDLING:
- Trained on real degradations like blur, noise, and compression

WHY NOT OTHER OPTIONS?

- ESRGAN: Older version, less refined output
- SwinIR: Slower inference with similar quality
- SRCNN / FSRCNN: Lower quality, visible artifacts


KEY ADVANTAGES:
1. Handles real-world degradations
2. Native 4x upscaling with high fidelity
3. Preserves metallic textures and fine jewelry details
4. Actively maintained with good documentation


--------------------------------------------------
2. GENERATIVE ENHANCEMENT: STABLE DIFFUSION + CONTROLNET
--------------------------------------------------

WHY STABLE DIFFUSION?

Stable Diffusion 1.5 combined with ControlNet Tile is used for generative
refinement while preserving original structure.

KEY BENEFITS:
- Strong structure preservation using ControlNet
- High-quality texture generation
- Full control over prompts
- Can be deployed locally on GPU

WHY CONTROLNET TILE?

ControlNet Tile is used to:
- Maintain original structure
- Preserve colors and shapes
- Enhance details without hallucinating new elements

CONFIGURATION CHOICES:
- Generation strength: 0.3 (preserves original)
- Steps: 25 (balance between quality and speed)
- Guidance scale: 8.0 (strong prompt adherence)

PROMPT STRATEGY:
Luxury jewelry, professional product photography,
crystal clear, sharp focus, metallic shine,
gemstone sparkle, high-end catalog quality


--------------------------------------------------
3. BACKGROUND REMOVAL: U2-NET (REMBG)
--------------------------------------------------

WHY U2-NET VIA REMBG?

The rembg library uses U2-Net for accurate background removal.

KEY BENEFITS:
- Clean and sharp edges
- Fast local inference
- Free and open-source
- Very accurate for product images

WHY NOT OTHER OPTIONS?

- Remove.bg: Paid cloud API with privacy concerns
- MODNet: Optimized for portraits, not products
- DeepLabV3: General segmentation, weaker edge quality


KEY ADVANTAGES:
1. Product-optimized segmentation
2. Smooth alpha matte
3. Fully local processing
4. No manual intervention required


--------------------------------------------------
4. VISION LANGUAGE MODEL: MINICPM-V / LLAVA
--------------------------------------------------

WHY MINICPM-V OR LLAVA?

MiniCPM-V and LLaVA are used through llama.cpp for local vision-language tasks.

KEY BENEFITS:
- Fully local deployment
- No API costs
- Better privacy
- Low latency
- Good classification accuracy

MINICPM-V 2.6:
- Compact size (~4GB quantized)
- Strong visual reasoning
- Runs on consumer GPUs

LLAVA 1.6:
- Strong image understanding
- Well-documented
- Multiple model sizes
- Large community support

WHY NOT OTHER OPTIONS?

- GPT-4 Vision: Expensive and cloud-only
- Claude Vision: Cloud-only
- Gemini Vision: Cloud-only with rate limits
- BLIP-2: Less conversational
- Custom CNN: Requires training data and lacks flexibility

USE CASES:
1. Jewelry type classification
2. Color detection
3. Material analysis
4. Style description

PROMPT DIFFERENTIATION:
WATCH:
Is this a WATCH with a clock face that tells time?

BRACELET:
Is this a BRACELET? Decorative wrist jewelry without a clock face.


--------------------------------------------------
5. VIRTUAL TRY-ON IMPLEMENTATION
--------------------------------------------------

WHY SIMPLE PLACEMENT?

A simple landmark-based placement approach is used instead of full AI try-on.

BENEFITS:
- Fast and reliable
- Works offline
- Low hardware requirements

LIMITATIONS:
- Less photorealistic integration

WHY NOT FULL AI TRY-ON?

- IDM-VTON / OOTDiffusion: Clothing-focused
- DressCode / VITON-HD: Designed for apparel
- 3D Rendering: Requires 3D jewelry models
- AR-based solutions: High complexity

CURRENT IMPLEMENTATION:
1. Pre-generated person images (Pollination / Flux)
2. MediaPipe landmark detection
3. Alpha blending
4. Type-based positioning:
   - Rings: Finger
   - Bracelet / Watch: Wrist
   - Necklace: Neck / chest
   - Earrings: Ear

FUTURE IMPROVEMENTS:
- Jewelry-specific datasets
- AI-based try-on models
- 3D reconstruction pipelines

7. VISION LANGUAGE MODEL (VLM) FINE-TUNING STRATEGY
--------------------------------------------------

CURRENT STATUS

At the current stage, the Vision Language Model (MiniCPM-V / LLaVA) has NOT been
fine-tuned specifically for the jewelry domain.

Despite this, inference-only usage with careful prompt engineering has achieved
approximately 85% accuracy for tasks such as:
- Jewelry type classification
- Basic color identification
- Material inference
- Style categorization

This indicates that the base model already has strong general visual reasoning
capabilities.

The remaining errors are mainly observed in:
- Visually similar categories (e.g., Bracelet vs Watch)
- Subtle material differences
- Edge cases with occlusions or low lighting


WHY FINE-TUNING IS STILL IMPORTANT

Although inference-only performance is strong, fine-tuning is expected to:
- Improve classification consistency
- Reduce ambiguity between similar jewelry types
- Increase robustness to real-world variations
- Improve domain-specific understanding

Fine-tuning is planned as a future enhancement once sufficient curated data is
available.


PLANNED FINE-TUNING APPROACH

The fine-tuning strategy will use parameter-efficient methods to avoid full model
retraining.

1. LoRA (Low-Rank Adaptation)
   - Injects trainable low-rank matrices into attention layers
   - Keeps the base model frozen
   - Requires significantly less GPU memory
   - Allows fast experimentation and iteration

2. QLoRA (Quantized LoRA)
   - Combines LoRA with 4-bit / 8-bit quantization
   - Further reduces memory usage
   - Enables fine-tuning on consumer GPUs
   - Maintains near full-precision performance


WHY LoRA / QLoRA OVER FULL FINE-TUNING

- Full fine-tuning is expensive and slow
- Requires large datasets and high-end GPUs
- Risk of overfitting on small datasets

LoRA and QLoRA provide:
- Faster training
- Lower compute cost
- Safer adaptation without catastrophic forgetting
- Easy rollback and experimentation


EXPECTED FINE-TUNING PIPELINE

1. Curate a jewelry-specific image + text dataset
2. Define task-specific prompts and labels
3. Apply LoRA / QLoRA adapters on vision and language layers
4. Train with low learning rate and limited steps
5. Validate improvements against inference-only baseline
6. Merge or load adapters during inference as needed


EXPECTED OUTCOME

With domain-specific fine-tuning:
- Accuracy is expected to improve beyond 90%
- Reduced confusion between similar categories
- Better consistency across lighting and backgrounds
